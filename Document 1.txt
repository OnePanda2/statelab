# 2. What is StateLab?

StateLab is a desktop research platform for studying **deterministic state evolution systems**.

The application is designed to compute, analyze, visualize and compare deterministic mathematical systems through a unified research environment.

Version 1 ships with one built-in system:

- Classic Collatz

However, the software itself is **not a Collatz application**.

It is a general-purpose deterministic state evolution laboratory whose architecture has been designed to support future systems without redesign.

Examples of future systems include:

- Generalized Collatz
- 5n + 1
- ax + b Systems
- Cellular Automata
- Graph Walkers
- Tree Evolution Systems
- Vector State Systems
- User-defined deterministic systems

The software studies deterministic evolution itself.

It does **not** claim that any deterministic system is random.

It does **not** claim cryptographic usefulness.

It does **not** claim superiority over existing PRNGs.

The purpose of the application is observation, experimentation, visualization and mathematical research.

---

# 3. Project Origin

The project originally began as a VLC companion application intended to improve shuffle fairness.

While researching randomness, attention shifted toward deterministic mathematical systems, especially the Collatz Conjecture.

During that research a more interesting question emerged.

Instead of asking

> "Can Collatz generate randomness?"

the project began asking

> "How does information evolve inside deterministic systems?"

That question fundamentally changed the scope of the project.

The application evolved from a visualization tool into a research platform.

The architecture now intentionally separates:

- deterministic computation
- feature extraction
- visualization
- analysis
- comparison
- export

so that no single mathematical system is embedded into the software itself.

Classic Collatz is simply the first implementation.

# 4. Engineering Philosophy

The project follows several non-negotiable principles.

## 4.1 Mathematical Correctness First

Correct mathematics always takes precedence over performance.

No optimization may change mathematical behavior.

---

## 4.2 Reproducibility First

Every experiment must be reproducible.

Every export must contain enough metadata to recreate identical results.

---

## 4.3 Separation of Responsibilities

Each subsystem has one responsibility.

The computation engine computes.

Feature extractors derive metrics.

Visualization renders.

Export serializes.

No subsystem performs another subsystem's work.

---

## 4.4 Single Source of Truth

Every mathematical result originates from the State Evolution Engine.

Visualizations never recompute trajectories.

Analysis modules never alter trajectories.

Exports never invent missing data.

---

## 4.5 Immutable Data

Trajectory Objects are immutable.

Once created, they may never be modified.

Derived data produces new objects.

Original computation is never mutated.

---

## 4.6 Architecture Before Features

Features are added only after they fit the architecture.

The architecture is never changed simply to make a feature easier.

---

## 4.7 Deterministic Behavior

Given identical:

- deterministic system
- version
- configuration
- initial state

the engine must always produce identical output.

No hidden randomness exists anywhere in the engine.

# 10. Definition of Success

The project is successful when:

- Mathematical correctness is verified.
- Architecture remains intact.
- Every subsystem is independently testable.
- Results are reproducible.
- Future deterministic systems can be added without architectural redesign.
- Visualization accurately represents computed data.
- Researchers can perform deterministic state evolution experiments through a unified desktop environment.

The goal is not merely to build software.

The goal is to build a reliable research platform whose architecture can support years of future mathematical exploration.
